# ADR-003：使用有符号 int64 纳秒表示分析时间

- 状态：MVP 已接受
- 日期：2026-09-05

## 背景（Context）

规则包含毫秒甚至更细粒度的边界。浮点秒会产生累积舍入误差，而 `datetime` 会把墙上时间与单调经过时间混在一起。

## 决策（Decision）

在单调分析时间轴上，以有符号 64 位整数纳秒表示 TimePoint 和 Duration。带单位的 Duration 文本必须精确解析。墙上时间单独保存为 Provenance。Adapter 的转换和舍入策略必须记录。

## 备选方案（Alternatives）

- 浮点秒：简单，但精确 Deadline 不可靠。
- 整数微秒：多数 CAN 日志够用，但会无必要地丢失已有精度。
- `datetime`/`timedelta`：偏向墙上时间、更重，并且仍无法回避源时间转换决策。
- 任意精度整数：精确，但开销没有必要，与列式格式互操作也较差。

## 影响（Consequences）

Deadline 比较精确，并易于与常见数据工具互操作。必须进行范围检查和防溢出运算。可表示约 292 年，远超单次分析 Session。
